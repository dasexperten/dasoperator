---

## Суть в двух строках

Целая ветка маркетплейс-джоб (отзывы, вопросы, продажи) тихо сгнила и была невидима мониторингу. Причина оказалась приземлённой — в Worker сидел пустой ключ DeepSeek вместо рабочего. По ходу: перевёл генерацию ответов на gpt-5.5 (ChatGPT OAuth) через новый мост, починил ещё три отдельных бага и закрыл слепое пятно watchdog.

---

## Симптом

На странице /reviews самые свежие WB-отзывы стояли на 12 июня (18 дней назад). На уровне Worker всё было «зелёное» (errors: 0), инфраструктурного обвала не было — значит тихие логические падения внутри крон-обработчиков.

---

## Корневые причины и что сделано

### 1. WB reviews — встали 12 июня
- Что: генерация ответа падала на каждом отзыве с `HTTP 402 Insufficient Balance`. Ингест отзывов был жёстко сцеплен с генерацией — строка в БД пишется только после успешного драфта, поэтому новые отзывы не сохранялись вообще.
- Почему: в секрете Worker `DEEPSEEK_API_KEY` был зашит другой, ДРЕНИРОВАННЫЙ ключ. Рабочий ключ ($46 баланса) всё это время лежал в инструкции проекта / SECRETS. Atlas Cloud DeepSeek мёртв с 15 июня.
- Фикс: поставил в Worker funded-ключ из инструкции (CF API, без редеплоя). Отзывы пошли в ту же минуту — +347 строк, потом стабильный поток.

### 2. Ozon reviews + Ozon/WB questions — 9–12 дней простоя
- Что: cron `40 */6` дёргал сам себя по публичному адресу `dasoperator-api…workers.dev/api/mp/sync-all`.
- Почему: Cloudflare режет вызов воркера в самого себя через публичный домен ошибкой 1042 (same-account loop). Падал каждые 6 часов в тишину.
- Фикс: cron теперь вызывает `runMpFeedsSync(env)` напрямую in-process, с записью heartbeat в marketplace_sync_log по каждому каналу. Ozon reviews подтянулись (1818 строк), вопросы освежились.

### 3. Ozon sales — 33 часа простоя
- Что: sales-синк умирал на одном `HTTP 429` (Ozon seller-api ~2 запроса/сек).
- Фикс: экспоненциальный backoff на 429 в `fetchOzonAnalytics` (1s→2s→4s→8s→16s) + интервалы между страницами. Синк снова ok.

### 4. Watchdog — слепое пятно
- Что: watchdog следил только за stocks и sales. Reviews и questions не мониторились вообще — поэтому 18-дневный простой прошёл незаметно.
- Фикс: добавил в MP_RULES каналы ozon-reviews / wb-reviews / ozon-questions / wb-questions + heartbeat в runWbAutoReply. Теперь тихий простой этих джоб поднимет тревогу.

### 5. Генерация ответов → gpt-5.5 (ChatGPT OAuth) primary, DeepSeek фолбэк
- По твоему требованию: reply-генерацию перевёл на gpt-5.5.
- Ограничение: Worker не может звать ChatGPT OAuth напрямую (device/CLI-сессия, см. SECRETS/openai.md). Поэтому поднял мост.
- Цепочка write-гейта: gpt-5.5 (мост) → deepseek-chat (быстрый, не reasoning) → Claude OAuth (страховка, чтобы генерация НИКОГДА молча не вставала).
- Гоча: аналитические гейты используют deepseek-v4-pro (reasoning) — его нельзя брать на короткую генерацию ответа (сжигает лимит токенов на рассуждения и отдаёт пусто). Поэтому фолбэк write-гейта — deepseek-chat.
- KV `codex:cooldown-until`: при исчерпании квоты gpt-5.5 ставится cooldown 20 мин, чтобы не тратить ~8с/отзыв на заведомо провальный вызов.

## Новая инфраструктура: codex-bridge

- Хост: hermes-vps 46.225.176.205, systemd `codex-bridge.service`, uvicorn FastAPI на 0.0.0.0:8789, код /root/codex-bridge/app.py.
- Что делает: принимает POST /v1/generate (HMAC, header X-Bridge-Signature) → запускает `codex exec -m gpt-5.5` → отдаёт текст. При провале codex (обычно квота) отдаёт 502, Worker уходит в фолбэк.
- Доступ: сырой IP по HTTP (ufw открыл 8789). НЕ через субдомен dasexperten.com — этот домен вообще не резолвится публично (NS делегированы не на Cloudflare), поэтому CF DNS + Caddy TLS там мёртвый путь. Тот же паттерн, что telegramer/anthropic-bridge.
- Worker secrets: CODEX_BRIDGE_URL=http://46.225.176.205:8789, CODEX_BRIDGE_HMAC_SECRET.
- Клиент в Worker: api/src/lib/openai-codex.ts.
