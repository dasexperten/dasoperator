# Залина: текущие 627 ₽ и чтение Instagram-изображений

Владелец сопоставил текст в Instagram с 627 ₽ и строку ERP с 1611 ₽; затем потребовал исправить чтение присылаемых изображений.

## Сверка денег

Аккаунт: `zalina.alkhsv_obzor`. В старом реестре три строки 529, 541, 544: 456 + 456 + 699 = 1611 ₽. Это исторический итог строк, не подтверждение исполнения переводов и не сумма новой корзины. Повторы сохранены по прежнему решению Владельца.

В Direct от 17.10.2026 есть полные текущие реквизиты и явно написанный итог 627 ₽. Новая выплата отсутствовала. Создана отдельная запись `ugc_recovered_501088175a22f04887f06b9a`: 62700 minor RUB, awaiting_approval, реквизиты заполнены из исходного сообщения. Перевод не выполнялся, Konsol payment id отсутствует. В живом ERP проверена активная кнопка оплаты 627 ₽. Продукт текущей корзины не выдумывался; INNOWEISS в строке происходит из старой базы.

Текущий профиль Instagram показал 9361 подписчика, в ERP был старый снимок 9367. Обновлено до 9361 с датой проверки.

## Найденная ошибка

Состояние последнего входящего сообщения: `image_read_failed`, три попытки, needs_review. Ошибка более ранней картинки останавливала обработку до чтения нового текста. Сохранённая ссылка изображения от 16.10 возвращала HTTP 404; прямое обновление по старому идентификатору сообщения — ошибку Meta 9000001. При чтении текущих 51 сообщений диалога запись того изображения не найдена. Это не доказывает, что фотография никогда не присылалась: её метаданные были сохранены в ERP.

## Исправление

- Новые входящие изображения сохраняются сразу при получении в приватный DOCS/R2. Для `das-erp-docs-dev` проверены выключенный публичный R2-домен и отсутствие custom domains. Публичные ссылки на личные изображения не создаются.
- Чтение сначала обращается к сохранённым байтам. Просроченный CDN больше не является единственным источником.
- Обновление вложения идёт через диалог; при отсутствии совпадения id допускается только однозначное совпадение времени и отправителя.
- Старое недоступное изображение не скрывает более новое читаемое. Недоступность учитывается отдельно; модель не утверждает, что прочла отсутствующую картинку.
- Если изображения недоступны, новая полная текстовая сумма, телефон, банк и ФИО могут зарегистрировать текущую выплату. Каждый реквизит сверяется с текущим входящим текстом. Без такого подтверждения нет подтверждения блогеру и нет выдуманной выплаты.

Проверки включают сохранение байтов в приватном хранилище, чтение после имитации истечения CDN, старое плохое + новое читаемое изображение, полный текст при неработающей картинке, отказ при недостаточном тексте, безопасное обновление вложения. Инструкции и актуальные четыре карточки из `origin/main` сохранены. Проверочные сообщения блогерам и реальные платежи не отправлялись.
