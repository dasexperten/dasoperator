# Bounded integration path and remaining prerequisites

This checkpoint verifies a local data-integrity path. It does not enable a
production migration or replace source authorization with synthetic assertions.
Preliminary contact remains in the existing Sheet; response plus deliberate
substantive discussion precedes ERP ownership. GitHub still supplies code and
system rules. Existing operational Git writes continue until the whole route is
verified and switched deliberately.

## Implemented local path

1. Keep the original source-case identity and qualification checkpoint immutable.
   Initial transfer uses the default-off handoff service against the pinned real
   UGC definitions, with exact IDs, alias/manual-state checks and atomic readback.
2. Explicitly enroll the resolved creator in manual-record revision observation.
   Pin that revision at the coherent source checkpoint, not immediately before
   execution to bless stale evidence. Compose its check into the verified handoff
   guard before replay handling. Observation starts at enrollment and does not
   invent prior history or cover lifecycle-only changes outside the manual table.
3. Use the alternative mapping schema only as a reviewed whole. It retains
   immutable original identity and selected human snapshots, while live foreign
   keys point to the versioned current mapping. It is not a complete archive of
   deleted content, messages or metrics.
4. At the existing authenticated merge route's batch boundary, preserve all
   original request/platform/identity validation and wrap its original SQL in the
   transaction-scoped merge coordination. Resolve the survivor by actual IDs.
   Do not expose coordination rows or arbitrary SQL to request metadata.
5. At the recurring cleanup batch boundary, re-evaluate current eligibility in
   the same transaction before the original marker/deletion statements. A stale
   selection must cause no marker or data loss. Other destructive writers remain
   blocked for mapped records until explicitly integrated; original unmapped
   paths retain their existing behavior.
6. After a lost response, reconcile the permanent source key and current mapping.
   Read-only identity resolution is not a new transfer approval or permission to
   contact/publish. Tombstoned and ambiguous identities cannot become fresh cases.

The supported composed schema and exact pinned merge/purge statements are tested
locally. No production router, cron, binding or migration is changed by this
checkpoint. Existing history-FK merge failures are retained, not silently repaired.

## Required before enabling any real writer

- **Real source contract:** assign and verify stable Sheet case/action identities
  and machine-readable receipts without damaging existing A:P fields. Establish
  complete coverage across Sheet and ERP history, coherent qualification/manual
  checkpoints, deletion/DNC history and authoritative new-ID allocation. Prose,
  checkmarks, missing rows and numeric zero cannot substitute for that evidence.
  Writer and counter must be verified together across later scheduler invocations.
- **Actual caller authorization:** use an explicitly authenticated, scoped
  integration. Public UGC routes already require an ERP session and module access;
  the global middleware's observe mode is not protection for a new route. A
  fixture verifier, database binding or coordination row is not authorization.
  Unattended/local agents do not gain service access merely from these helpers.
  No new credentials, persistent grants or security configuration are provided.
- **Current environment and writers:** verify deployed schema, installed jobs,
  all relevant write paths, pending/unknown publications and existing queue locks.
  Preserve Angela's approvals, scheduling distinction, D1 CAS baseline and R2
  markers. Source snapshots do not establish deployment state.
- **Verified isolation:** prepare an effective test environment with synthetic
  data and explicitly isolated dependencies before remote testing. Empty API
  preview settings or a preview URL do not prove frontend isolation. Production
  resources with dev-like names must not be reused as test resources.
- **Change authority and retention:** obtain any required specific approval for
  new persistent access and remote configuration, and resolve the intended
  retention/privacy policy for permanent identity/human-state metadata. Notify
  before production switching, as promised. Merge, deployment, live schema/data
  writes and outreach are not authorized by a passing fixture suite.

Once these prerequisites are established, integrate the narrow route/batch points
above, run the same failure scenarios in the verified isolated environment, and
reconcile an explicit cutover boundary. Rollback preserves both stores, receipts,
case history, unknown outcomes and delivery locks. It never means deleting the new
store, resetting queues or replaying external actions from an older snapshot.
