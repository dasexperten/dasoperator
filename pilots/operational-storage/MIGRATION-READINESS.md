# Migration readiness and next implementation gates

Status: local, disabled implementation preparation. This is not a production
migration, a completed transfer, or a reduction in current operational commits.
GitHub remains authoritative for code and system rules. The confirmed business
boundary is preliminary contact/comments in the existing Google Sheet, followed
by ERP case ownership only after a response and deliberate substantive discussion.
No response, action count, archive receipt or metadata assertion grants permission
to transfer, contact again, publish, or change a manual stage.

## What is established locally

  context revisions, legacy export-marker preservation, default-preserving Git
  writer seams, reconciliation and their failure-path tests exist.
- The real Diana parser contract is pinned. Disabled Sheet diagnostics do not
  infer receipts from prose, dates, links or checkmarks and never return live
  totals. Real runner tests distinguish a count exception from numeric zero.
- The hybrid planner binds agent, workbook, tab, case, source checkpoint, reply
  and deliberate decision, retaining manual stages including an empty value.
- The local recovery journal keeps one source-case fence and one opaque ERP
  identity through uncertain outcomes and failed Sheet acknowledgments. It
  cannot execute a transfer. Independent local SQLite connections and file
  reopen tests do not prove Cloudflare transaction or power-loss behavior.
- Pinned source inspection identifies current API, rename, merge, manual-stage
  and cleanup contracts. See ERP-HANDOFF-CONTRACT.md. Deployed versions and live
  state have not been established by that source inspection.
- Detached atomic handoff persistence now runs against hash-verified, reconstructed
  UGC schema in local native D1 tests. It preserves existing fields and exact IDs,
  rejects stale manual/alias state, and atomically rolls back late failures and a
  stale cleanup batch. See ERP-HANDOFF-PERSISTENCE.md. The source projection and
  verifier are still synthetic, and no route or deployed schema is changed.
- Structured receipt preparation preserves immutable origin and exact action
  evidence. Whole-batch bounds reject malformed observations before parsing or
  counting. This does not assign live Sheet identities, write a receipt or provide
  authenticated totals.
- The composed local alternative adds explicit manual-record revision enrollment,
  checks that revision before replay handling, and retains permanent source-case
  history with versioned live identity. Exact original merge and recurring-purge
  SQL are exercised with transaction-scoped coordination and current eligibility.
  See INTEGRATION-PATH.md for the bounded adoption points and remaining gates.

   existing A:P display fields, preserve original action evidence and record
   source checkpoints/coverage explicitly. Existing prose cannot be converted
   into verified receipts automatically. Missing or partial history must stop
   work visibly; it must not look like zero. Verify behavior across later
   scheduled invocations, not just one failing runner call.
2. **Stable handoff identity and decision provenance.** Row position and handle
   are not stable case identities. Persist and verify an explicit source-case
   mapping, qualifying response reference, substantive decision and relevant
   version/checkpoint. Re-read current identity, stages and deletion/DNC state
   before any transition. Reconcile the canonical Git rules and installed job
   prompts with the latest confirmed storage boundary before activation; pilot
   documentation does not change running policy. Metadata strings in these pilots do not authenticate
   a qualification decision or prove source completeness.

   no complete qualified-handoff endpoint. The detached candidate now passes
   tests against actual pinned table definitions, but is not connected to live
   tables or authenticated sources. Import cannot create a new
   non-Instagram discussion case; payouts must not be used to fabricate an
   agreed card. Resolve actual existing profile/creator IDs and aliases,
   preserve concurrent human decisions, atomically retain one handoff identity,
   and verify readback. Unknown creation outcomes must be reconciled against

   Existing manual-stage storage has no version field. The local observer detects

4. **Deletion and platform coverage.** Recurring Instagram purge markers do not

   approved flag is not publication authority. Existing native platform

6. **Authorized isolated runtime.** Local workerd tests are isolated; a Pages

   no bindings, while the frontend uses the production API. Verify an effective
   isolated configuration and all write-capable dependencies before any remote

7. **Real reader/writer coverage and durable recovery.** Connect all applicable
   operational writers and readers, including local sessions and shared
   exporters. Durable archive-event retention, result recovery and actual
   source authorization remain prerequisites. No silent fallback to Git or
   missing memory is acceptable after an eventual source switch.

## Switching and rollback

Production switching requires advance notification and the necessary authority.
Do not merge, deploy, add live receipt fields, apply schemas, change schedules,
create grants, import personal data, contact people or publish as part of these
local tests. Technical implementation choices do not remove those boundaries.

A future switch must reconcile a recorded boundary before enabling a new writer,
retain old links and identifiers, and verify that old and new sources cannot both
trigger an external action. Rollback means disabling the selected route and
reconciling records written since the boundary. It does not mean deleting the
new store, resetting a queue, clearing delivery locks, changing stages, or
blindly reenabling an old publisher with stale state. Keep unknown outcomes
unknown until independently resolved.
