# workers-backup/

Recovered source snapshots of Cloudflare Workers whose original source repo
(`dasexperten/arams-db`) was deleted on 2026-07-04.

**Why this exists:** these Workers keep running fine on Cloudflare (a deployed
Worker doesn't need its GitHub repo to serve traffic), but before this backup
there was no source anywhere to start from if any of them ever needed a code
change. Each subfolder here is the live bundle pulled directly from Cloudflare
via `GET /accounts/{account}/workers/scripts/{name}` on 2026-07-04, plus a
`bindings.json` describing its current bindings/vars/cron (names only —
Cloudflare never returns secret values via API; re-set those from
`SECRETS/cloudflare.md` before any redeploy).

| Worker | File | Cron | Bindings |
|---|---|---|---|
| `promozon` | `promozon/index.js` | `0 */4 * * *` | D1 `DB`, 5 secrets (Ozon Performance/Seller API) |
| `emailer-bridge` | `emailer-bridge/worker.js` | none | none |
| `rumailer-bridge` | `rumailer-bridge/index.js` | none | `CF_ACCOUNT_ID`, `DOMAIN`, `RESEND_API_KEY` |
| `browser-run-bridge` | `browser-run-bridge/index.js` | none | `BRIDGE_SECRET`, `CF_BROWSER_TOKEN`, R2 `OUTPUT` |

Not touched / not affected by the arams-db deletion (already Cloudflare-native
or already migrated off arams-db before deletion): `marketplace-sync`,
`dasoperator-api` (source lives in this repo under `api/`), `reviewer-ozon-reviews`
(replacement for the old hermes-vps Ozon review cron — see `das-reviewer/README.md`).

**Known real gap, NOT covered by this backup:** the Ozon/WB FBO stock
recommendation feed (`docs/ozon-fbo-status.json`) was generated by GitHub
Actions cron only inside `arams-db` (`ozon-fbo-monthly.yml`, `wb-fbo-monthly.yml`)
and read client-side by `dasoperator.pages.dev/marketplaces` from
`raw.githubusercontent.com/dasexperten/arams-db/...` — that URL now 404s.
This needs to be rebuilt as a Cloudflare Worker cron (candidate: extend
`promozon` or a new `ozon-fbo` Worker) — tracked separately, not part of this
source-recovery pass.
